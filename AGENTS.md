# Working on RTLPlayground

Before drafting a commit, pull request, push or comment, read `CONTRIBUTING.md`. Its "you" is the contributor; help them meet it. The rules below cover how agents work with the contributor in this checkout. Pass both to any approved agents.

## Stay within the request

Answer a question with an answer; change code only when asked. Report what an investigation uncovers and let the contributor choose what to fix.

For a larger change, agree on the scope before writing it. Ask before adding work, involving other agents or setting up background automation.

Preserve local configuration and stop when the requested work is done.

## Ask before publishing

Approval under `CONTRIBUTING.md` means showing the contributor the exact text or diff and where it will go, then waiting for their answer. It applies to posting, pushing and every other remote change, including personal forks, draft PRs, reviews, comments, edits and screenshot uploads.

Approval covers exactly what was shown; later replies and related changes need their own. If the request is ambiguous, ask. Correcting an earlier public mistake also needs approval.

Report only review and testing that actually happened.

Flashing, rebooting, changing configuration and writing registers each need separate approval for the named devices. Approval to build or test does not cover them.

## Avoid extractive contributions

An extractive contribution costs maintainers more to process than it is worth. Before posting, read the discussion, search existing issues and PRs, and check which patch introduced a problem. Include the repository name when a reference could be ambiguous.

Post each finding once, in its proper thread. Send a message only when it adds evidence or answers a question; keep running updates and unrequested tracking issues out of public threads.

## Write like a contributor

Follow "Edit what the tool writes" in `CONTRIBUTING.md`. Most comments need two or three sentences. Keep long notes locally.
