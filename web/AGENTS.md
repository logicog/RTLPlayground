# Frontend conventions

- Keep source files readable. Minification belongs exclusively to build output in `html/`.
- Use system fonts only. Do not download fonts or add external font services. Keep controls and meaningful labels legible on desktop and mobile; do not shrink them to fit more columns.
- Omit marketing copy, repeated device-model headings and generic instructions such as “click a port to configure it”. Keep concise action labels, actual device state, draft state and specific validation messages.
- Port clicks edit local drafts directly where the operation is discrete (aggregation membership, EEE, mirroring and administrative state). In VLAN editing, clicking the port body selects its persistent inline settings panel; clicking its membership badge cycles the draft state, without excluding a port from its PVID. Make other editable state badges interactive too, with keyboard access and an explicit next-action label. Do not use popup menus or a global VLAN action mode. Only an explicit review and apply step may send configuration commands.
- Confirm before navigation or refresh would discard unapplied changes, and warn on browser reload or tab closure. Cancelling must preserve the route, selected port and all drafts. Switching ports, VLANs or inspector tabs should preserve drafts without prompting when nothing is lost. Reverting fields to their original values must clear the dirty state. Keep unapplied drafts separate from changes already applied but not saved to startup configuration.
- Saving startup configuration must not trigger a download. Keep Export configuration as an explicit action in Settings. Show draft and startup-save status in the shared header, with a Save action available across routes.
- Save automatically is an opt-in browser preference, off by default. Write startup configuration only after a fully successful Apply, never on draft edits, polling, navigation or merely enabling the preference. Preserve existing startup commands, enforce the storage budget and verify writes by reading them back. Keep failed or uncertain saves visible and do not automatically resend them.
- Assigning a port to an aggregation group replaces its previous group membership in the draft. Review all affected groups together and release moved ports before assigning them to their new groups. Discard restores the whole aggregation draft.
- Show one Review action per view, covering its pending edits. Do not add separate review buttons for port tools, the selected port and global settings on the same page.
- Assign group and VLAN colors by stable numeric ID through the shared entity-color helper. Keep matching colors across selectors, port annotations, inspectors and routes; adjust brightness for dark mode without changing the hue.
- Aggregation details describe the selected group, not the last clicked port. Keep the group summary compact and omit the redundant port header and raw hash-register value.
- Use focused Lit components, typed data models and named event handlers. Keep command construction and validation outside templates.
- Use early returns or a switch instead of nested conditional expressions. Do not put multi-step operations in template event bindings.
- Prefer cards, port diagrams and focused editing panels. The user explicitly rejected classic tables.
- Make physical ports the primary view. Keep port details in context and show tagged membership, untagged membership and PVID separately. Missing membership data must appear as unknown, never as an excluded port.
- Reuse the same device-front component in VLAN editing. Select a port and show explicit membership choices with a separate PVID control; do not return to a grid of per-port dropdowns.
- Use neutral gray surfaces and a blue interaction accent. Reserve green for small link indicators. Distinguish VLANs with both text and color.
- Preserve port drafts across polling, inspector tabs and port selection. Reading or selecting a port or VLAN must never issue a configuration command.
- Read files directly and make reviewable edits with patches. Do not use Python or other scripts to rewrite source files.
- The user has authorized Playwright to inspect the development preview. Use the available browser and simulated data; browser checks must not change the physical switch.
- Development preview must not write to the physical switch. Keep simulated data visibly identified and excluded from production builds.
- Follow the root rules for device safety, configuration preservation and Git publication.
- Login requests must explicitly set `Content-Type: application/x-www-form-urlencoded`. The firmware's `is_word()` parser rejects the `;charset=UTF-8` suffix automatically added by `fetch` for `URLSearchParams`. Local login tests must reject this suffix too; a permissive HTTP mock missed a real device failure.
- Both initial login and session renewal must use `loginRequest()` and `verifyLoginResponse()` from `domain/session.ts`. The standalone login script must be bundled so its shared imports remain self-contained in firmware HTML.
- The firmware supports only one HTTP connection. Load production CSS before importing the app, keep shared dependencies in one core chunk, disable module preloads and serialize route imports with API requests. Verify the packaged image against a server that rejects concurrent requests.
- Every port-oriented page uses the shared physical faceplate. Ports, aggregation, EEE, bandwidth, STP, mirroring and diagnostics use `renderPortWorkbench()` for the contextual layout; overview and VLAN editing retain the same faceplate and inspector positions. Preserve the selected physical port between routes.
- Show live link state and speed separately from feature annotations. Active links need a visible port accent and a strong speed badge; VLAN tagging needs explicit labels and different filled/outlined treatments, not only color.
- Automatic sign-out is a browser preference, not a firmware configuration command. Keep the session alive separately from live-statistics polling, enforce idle expiry, and preserve drafts during reauthentication. Browser suspension or another device login can still expire the firmware session earlier.
